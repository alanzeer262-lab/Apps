## Current implementation
- `scripts/align_narration.py`: measures narration duration, transcribes both MP3s using Faster Whisper word timestamps, matches spoken phrases to cue text, validates confidence/order, and writes the generated timeline.
- `scripts/sync-cues.json`: spoken phrase anchors for 14 scenes and key code/output/error/correction events.
- `scripts/requirements-alignment.txt`: alignment dependencies. Faster Whisper is pinned; `av<19` avoids a known incompatibility where Faster Whisper 1.1.1 passes `metadata_errors` to `av.open`, which PyAV 19 removed.
- `src/generated-alignment.json`: generated by the alignment script during the workflow; do not hand-edit as a substitute for running alignment.
- `src/lesson.ts` and `src/Video.tsx`: lesson scene/timeline and visual presentation.
- `package.json`: `npm run check`, `npm run render`, and `npm run align`.
- Workflow order: install Node dependencies → verify audio files → install Python alignment dependencies → align narration → TypeScript check → render MP4 → upload artifact.

## Synchronization algorithm
1. Read the two narration MP3 files.
2. Measure their actual durations using PyAV; the second file's timeline offset is the first file's duration.
3. Transcribe each track with Faster Whisper (`tiny.en`, CPU/int8, word timestamps).
4. Find spoken cue phrases using lexical similarity and token overlap.
5. Derive scene starts and code/output/error/correction event timestamps from those matches.
6. Stop the build when a required anchor is missing, too low-confidence, out of order, or outside its scene interval. Do not invent proportional or guessed timestamps.

This currently anchors major scene and visual events; it does not necessarily animate every individual keystroke.
